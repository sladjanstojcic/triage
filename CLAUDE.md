Triage is a local macOS dashboard (http://127.0.0.1:4777) showing listening ports, dev servers, Docker containers, SSH tunnels and remote VPS hosts, grouped by project folder, with confirm-before-acting stop/start buttons.

## Commands

pnpm 12 (pinned), Node 20.19+ or 22.12+ (Vite 8).

```bash
pnpm dev                 # tsx watch on src/server/index.ts; Vite runs inside it as middleware (HMR)
pnpm build && pnpm start # vite build -> dist/client, esbuild server -> dist/server.mjs
pnpm typecheck           # tsc (noEmit)
pnpm lint                # eslint
pnpm test                # node:test via tsx, all src/**/*.test.ts
pnpm exec tsx --test src/lib/grouping.test.ts                          # one file
pnpm exec tsx --test --test-name-pattern="sshUser" src/lib/grouping.test.ts  # one test
pnpm service:install     # build + LaunchAgent (scripts/launchd.sh); logs ~/Library/Logs/triage.log
```

`pnpm dev` and the LaunchAgent share the port, so stop one before starting the other; re-run `service:install` after changes. Env: `PORT`, `TRIAGE_HOSTS_FILE` (default `~/.config/triage/hosts.json`).

## Architecture

One Node process (`src/server/index.ts`, plain `node:http`, no framework) serves both the JSON API and the SPA. In dev it mounts Vite in middleware mode; in production it serves `dist/client` with an `index.html` fallback. Path alias `@/` → `src/` is used by both server and client code.

**Data flow.** The client polls `GET /api/snapshot` every 3 s and `GET /api/remote` every 30 s (`dashboard.tsx`, `use-polling.ts`; paused while the tab is hidden). There is no database or cache of state between requests apart from small in-memory caches (Docker disk usage, remote sudo check). Each poll re-runs the collectors.

**Collectors (`src/lib/collect/`)** shell out to system tools via `run()` in `src/lib/exec.ts` (`execFile`, no shell, never throws, returns `ok:false` on failure). A missing tool degrades to empty data plus an entry in `Snapshot.errors`, never a crash.
- `local.ts`: `ps` + `lsof` → listening processes, cwd, project/git info, and `stopPid` (the dev CLI parent such as `next dev`, not its worker).
- `origin.ts`: walks the process chain and launch env to name who started a server (agent / app / terminal) and whether the launcher is gone (`detached`).
- `snapshot.ts`: runs them and builds `PortRow`s by matching each listening port to a Docker container (via the Docker Desktop/OrbStack port proxy), an ssh forward, or a plain process.
- `remote.ts`: one read-only POSIX sh probe per host over `ssh -o BatchMode=yes`, output split into `##SECTION` blocks and parsed. Uses `sudo -n` when available (rechecked every 10 min, because a failed `sudo -n` writes to the remote auth log).
- `types.ts` holds every shared shape (`Snapshot`, `RemoteSnapshot`, `PortRow`, …) used by both sides.

**Pure derivation (`src/lib/`)**: `grouping.ts` (group by project, conflicts, container stacks, matching local tunnels to remote ports), `attention.ts` (Overview "Needs attention" list), `format.ts`. Views mostly call these rather than deriving data themselves. Tests live next to these files and the parsers in `collect/`, so put new logic where it can be tested without a UI.

**Actions (`src/server/actions.ts`)**: stop process, container start/stop/restart, remote equivalents, add/remove host (`src/lib/hosts.ts`, JSON file with serialized atomic writes). The client side of these calls is `src/lib/api.ts`.

**UI**: React 19 + Tailwind 4 + shadcn/ui (`base-nova` style, Base UI primitives; `src/components/ui/` is generated by shadcn). `src/components/dashboard/views/*` holds one view per tab. Tabs are defined in `src/lib/tabs.ts`, and each tab has its own URL path (`/projects`, …), handled client-side.

## Safety invariants (keep these when changing the server or actions)

There is no authentication, so the server is locked down instead:
- It binds `127.0.0.1` only and rejects any `Host` header other than `127.0.0.1:PORT`/`localhost:PORT` (DNS rebinding).
- Every `/api/` route except `GET /api/snapshot` and `GET /api/remote` requires `Origin` to equal `http://<host>` and `content-type: application/json` (forces a CORS preflight the server never answers). New state-changing routes must go below that check in `api()`.
- Every action **re-collects a fresh snapshot/probe** and only acts on pids/container ids that the scan currently offers as stoppable. The server never stops system processes or itself (`process.pid`/`ppid`).
- Remote commands are fixed strings; only validated numbers and hex container ids are interpolated. `SSH_TARGET_RE` validates ssh targets.
